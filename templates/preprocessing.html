資料前處理：從 train.csv 到 clean_train.csv

原始資料雖然包含完整的農業環境資訊，但其中有文字類別欄位、 不同尺度的數值欄位，以及不適合訓練的 id 欄位，因此需要先進行資料前處理。

原始資料概況

項目 內容
資料檔案 train.csv
資料筆數 630,000 筆
原始欄位數 21 欄
目標欄位 Irrigation_Need
分類結果 Low / Medium / High

為什麼需要資料前處理？

機器學習模型主要處理數值資料，要先檢查原始資料是否有缺失，同時資料中包含 Soil_Type、Crop_Type、Season、Region 等文字類別欄位， 需要將文字轉換為數字。此外，像 Soil_pH 與 Rainfall_mm 的數值範圍差異較大，也需要透過標準化降低尺度差異對模型訓練的影響。

clean_train.csv 產生流程

為了讓原始資料能被機器學習模型正確讀取與訓練， 我們將 train.csv 進行資料前處理，並輸出整理後的 clean_train.csv。 主要處理流程如下：

1

標籤數值化 Label Encoding

欄位：Irrigation_Need

改動：把 Low 轉成 0，Medium 轉成 1，High 轉成 2。

原因：灌溉需求具有強弱程度差異，數值化後能讓模型更容易處理分類目標。

2

欄位展開 One-Hot Encoding

欄位：Soil_Type、Crop_Type、Season、Region 等類別欄位。

改動：將原本單一類別欄位拆成多個 0 / 1 獨立欄位。

原因：這些類別本身沒有大小關係，例如黏土不一定比砂土「大」，因此使用 One-Hot Encoding 可避免模型誤判類別順序。

3

特徵縮放 Standard Scaling

欄位：所有數值特徵，例如 pH、溫度、雨量、濕度等。

改動：將不同數值欄位個別標準化，使資料尺度較一致。

原因：避免雨量這類數值範圍較大的欄位，在模型計算時完全蓋過 pH 值等數值較小欄位的影響。

4

格式統一

改動：將所有 True / False 格式統一轉換為 1 / 0。

原因：統一資料格式後，模型能以數值方式進行計算，避免不同資料型態造成訓練錯誤。

5

刪除用不到的 id 欄位

欄位：id

改動：將 id 欄位從訓練資料中刪除。

原因：id 只代表資料編號，沒有實際農業意義。若放入模型，可能讓模型學到無意義的規律。

前處理後的結果

經過上述處理後，原始資料中的文字欄位、布林值與不同尺度的數值欄位， 會被轉換成機器學習模型可使用的數值格式。最後輸出的 clean_train.csv 將作為後續非神經網路模型與 Keras / TensorFlow 神經網路模型的訓練資料。
